# P1-071: composite every visible video track (PIP)

No proto/FFI change (PreviewRenderer and Decoder are internal ports): no protocol bump.

## Model (core)
- `placement::covers_canvas(media, transform, canvas)`: a color always covers; otherwise the
  fitted, scaled, offset picture reaches every canvas edge (tolerance ~1e-6). Every layer is
  opaque today; blend modes / opacity (P3-011, P3-012) must revisit it.
- `Timeline::layers_at(time)`: visible video layers bottom to top, starting at the topmost one
  that covers the canvas (layers under it are never seen). No allocation.
- `layer_at(time)` = `layers_at(time).last()`; `top_clip_at` unchanged.

## Port and engine (app)
- `PreviewRenderer::draw(target, time, layers: &mut dyn Iterator<Item = Layer>)`, bottom to top.
- `Preview.drawn: Vec<LayerKey>` (capacity reused); redraw when the key list changes.
- Export draws `timeline.layers_at(time)`.
- Existing test fakes take `layers.last()` (mechanical, as P1-060 did when the signature changed).

## Render
- The first drawn layer clears to black and draws as before (shaders unchanged, pixel- and
  speed-identical). Later layers load and are scissored to the pixels whose centres show their
  picture (quarter turns only, so it is one rectangle). Discard cost ~21% (nv12) and blending
  ~12% on the host GPU (benches/draw.rs, interleaved with main); the scissor costs nothing.
- `draw_into` loops over the layers, drawing and waiting on each before the next decode (the
  decoder's frames live only until its next call). A layer that fails to decode is skipped and
  reported as Decode; the rest still draw.
- Android keeps drawing only the top layer (colors / test pattern); real compositing goes with
  its decoder (P1-070).

## Follow-ups
- iOS FrameDecoder keeps one reader / photo per media (two videos alternate = reopen per frame).
- One submit + wait per layer; a single submit needs frames that outlive the next decode
  (P1-053 render thread).
