Recurring review findings in Framix (first seen P1-008, 2026-10-15):

- Scope creep into already-planned tasks: config/profile tweaks (e.g. strip/LTO/codegen-units = SEC-020, debug symbol split = GOT-005) slip into an unrelated task branch while the owning task stays todo.
  **Why:** tasks.json has ~600 fine-grained tasks; almost any "extra" already has an ID.
  **How to apply:** for every non-test change outside the task title, grep tasks/tasks.json titles for it and flag as Warning naming the owning task.
  Seen P1-014 re-review: a dependency-age fix also downgraded crates already locked on main (libc, zerocopy); lockfile cooldown belongs to SEC-028/TC-003. Diff Cargo.lock against main and ask whether each changed crate is in the new dep's tree.

- `pub extern "C" fn` that dereferences a raw pointer carried inside a #[repr(C)] struct is declared safe; clippy's not_unsafe_ptr_arg_deref does not catch struct fields, so check.sh stays green.
  **Why:** ffi crate is also an rlib, so safe Rust can trigger UB.
  **How to apply:** check every exported fn taking pointer-bearing structs is `unsafe extern "C"` with a `# Safety` doc; note if fixing it would touch frozen tests (needs user approval).

- Stub-first test commits: verify each test actually fails against the stub; some (null/empty/None cases) pass on stubs. Seen again ENG-005 (Rate::new stub returned None, so the zero-parts test passed).

- Constructors accept a wider domain than the invariants hold for; proptests only sample the narrow "sane" range, so the gap is invisible. ENG-005: Rate::new allowed num > den*TICKS_PER_SECOND, breaking monotonic/round-trip; a frozen test even used such a rate.
  **Why:** frozen tests then lock in the invalid value, so the proper fix needs user approval.
  **How to apply:** for every validating constructor, check the property-test ranges cover the full accepted domain; compute a counterexample at the boundary.
  Seen again P1-014: insert_clip accepted negative start/source_start, so Timeline::duration() could go negative (testing.md "durations never negative").

- Pub-field structs whose methods rely on an invariant "checked at insert" (P1-014 Clip::end assumes start+duration fits). External code can build the struct literally and break it; release has no overflow-checks.
  **How to apply:** suggest `#[non_exhaustive]` (keeps pub reads, blocks outside literals, does not break frozen tests that read fields).

- Proptests that drop results (`let _ = op(...)`) and only check invariants pass trivially if the op rejects everything; ask for an Ok-iff-model check in a new test.

- Frozen-test edits: the user told the implementer not to ask for decisions, so testing.md "stop and ask" conflicts get resolved by a separate test-only commit before the impl commit (seen P1-023). Accept it only if the edit corrects a wrong model without dropping assertions AND the test still fails on the stub (a committed proptest-regressions seed that fails on the stub proves this deterministically). Require a task.py note so the human sees it.
  **How to apply:** diff test-commit..fix-commit, then fix-commit..HEAD on test paths must be empty.

- `prop_assume!(f(x).is_some())` gates on the function under test (ENG-048). OK only if (a) rejection rate is computed and tiny, (b) another test unwraps f over a provably-representable range (spurious None caught), (c) all-None still fails via proptest's global reject limit. Better: an independent oracle for the None condition.
  Also ENG-048: no app/.gitignore on main, so `flutter` runs leave generated app/ios, app/android files (absolute paths, gradle-wrapper.jar) that get swept into commits. Always check `git show --stat` for app/ generated files. (GOT-004 adds app/.gitignore from flutter create; still check for local.properties / Generated.xcconfig leaks.)

- `flutter create` template defaults committed unreviewed (GOT-004): Android label lowercase "framix" (app name is Framix), Gradle wrapper/AGP from the template not docs/toolchain.md, boilerplate README, `package:flutter/material.dart` + `uses-material-design` although toolchain.md says new code uses material_ui/cupertino_ui.
  **How to apply:** for any app/ scaffold or Gradle/Xcode change, diff versions and names against docs/toolchain.md and ADR 0001; pins belong to TC-002.

- Design drift from docs/architecture.md crate table without an ADR (P1-023: memento undo, while the table says core owns "undo commands"). Flag as Warning: update the table via a short ADR.

- Memento/snapshot undo also restores id allocators inside the snapshot (Timeline::next_id), so ids get reused after undo + new edit. Check any snapshot-restore code for allocator rollback.
  P1-043 fix bumped the counter (max) after each swap and made Timeline's PartialEq ignore next_id so frozen undo tests still pass. Side effect: `==` no longer proves two timelines behave the same, so any later round-trip test (save/load P1-009, crash recovery) can pass with a lost/zeroed counter -> duplicate live ids.
  **How to apply:** when a review touches serialization/restore of Timeline, require an explicit next-id check (e.g. add_track on both, compare ids), not just `==`. Also check ADR text that described the bug is updated when the bug is fixed.

- Generated-artifact leaks from "prove the check works" experiments (P1-007): implementer edited a Rust doc comment, ran `cbindgen --verify`, reverted the source but committed the header containing the edit. `cbindgen --verify` (0.29.4) WRITES the new header even when it fails, so a second check.sh run goes green while the tree is dirty.
  **How to apply:** for any committed generated file, always run check.sh and `git status` afterwards; restore with `git checkout -- <file>` if the check mutated it. Freshness checks should regenerate + `git diff --exit-code`, covering every generated layer (header AND Dart bindings), not just the first.

- Dart wrappers around native handles (P1-006 FramixEngine): no `_disposed` guard, so send-after-dispose or double dispose passes a freed pointer to Rust (UAF from safe Dart). Check every Dart class holding a Pointer for a closed-state guard.
  Same review: a "dispose closes the stream" Dart test passed on a `Stream.empty()` stub (stub-first pattern again; check Dart stubs too, not just Rust).

- New codegen tool added without pinning (P1-006: protoc unchecked in gen_ffi.sh, protoc_plugin/protox/buf missing from docs/toolchain.md "FFI codegen" row). For any new generator, require the version in toolchain.md and a version check in the script, like cbindgen.

- First-screen tasks absorb foundation tasks (ENG-003 did L10N-001 gen-l10n/ARB, DS-003 hand-built ColorScheme, ENG-002 bloc/get_it while those stayed todo). Flag Warning; ask for task.py notes on the owning tasks so they are not redone.
- Hand-built ColorScheme maps primary=accentFill (#6E4CF5); M3 OutlinedButton/TextButton then draw accentFill text on background = ~3.7:1, below the 4.5:1 rule (design-system says accentText for accent text on dark). Check component themes whenever a screen uses non-filled buttons.
- Generated l10n (app/lib/l10n/generated) committed but check.sh's `git diff --exit-code` only covers ffi/proto paths; flag until the l10n path is added (same family as the cbindgen freshness gap).
- Dart UI deriving display data from list position (ENG-003 "Video track {index+1}" across all kinds) = numbering/naming rule in Dart and wrong with mixed kinds; the engine should carry name/number.
- Cubits seeded with a Dart-made empty proto (ENG-003). ENG-050 added GetTimeline (async reply) but kept `super(TimelineChanged())`, pinned by a frozen "starts with an empty timeline" test, so a late cubit still shows empty/canUndo=false for one hop. Async-only FFI (engine_send enqueues) means a full fix needs a nullable/loading state.
  **How to apply:** for each new Bloc/Cubit check where the initial state comes from; flag Dart defaults that can disagree with the engine.
- Reviewer memory written to app/.claude/agent-memory/ when a run's cwd was app/ (found untracked 2026-10-15). Always write memory by absolute path under the repo-root .claude/; flag stray copies so they are not committed. Still untracked at ENG-049 review (2026-10-15): implementer runs flutter from app/, so it recurs; ask the implementer to delete it. Still there at TC-005 (2026-10-15).

- Overlapping tooling tasks: security/dependency tooling (cargo audit, cargo-deny, lockfile cooldown) is split across TC-003, TC-005, SEC-028, GOT-006. When one lands a piece, ask for task.py notes on the others so it is not rebuilt.

- Warning-gate scripts (TC-006 native_warnings.sh): check the allowlist for summary lines that stand in for many warnings. Gradle's default warning-mode is summary, so allowlisting "Deprecated Gradle features were used" hides every Gradle API deprecation, ours included; require `--warning-mode all` / org.gradle.warning.mode=all. Also check `grep ... || true` does not swallow grep exit 2 (bad regex = silent pass), and that a build failure prints the log before the trap deletes it.
  TC-006 re-review: ~/.gradle/gradle.properties and GRADLE_OPTS override the project file, so a dev-machine warning.mode=none silently passes the gate.
  TC-010 (2026-10-19): Xcode minor releases reword known warnings (27.1 "skipped, no" vs "skipped. No"); allowlist entries are unanchored substrings. For allowlist edits, test the regex with /usr/bin/grep -E (BSD) under bash, not the agent shell's grep (wrapped as ugrep), and confirm alternations are exact literals, not wildcards. check.sh does not run native_warnings.sh, and the reviewer may not run it either.

- User rewrites main history (trailer strip, 2026-10-15; backup/main-before-* branches). Branches forked before that have NO merge base with main (`git diff main...HEAD` fails). Check `git merge-base main HEAD` first; if empty, find the old fork commit with an identical tree on main and ask for `git rebase --onto main <old-fork>`.

- GPU/native-handle interop (P1-001 iOS spike, 2026-10-15): `// SAFETY:` comments assert facts the code could check cheaply (wrapped MTLTexture is on wgpu's device; caller-passed width/height/format match the handle). FFI fns also take sizes the handle already knows, so Dart/Swift can disagree with it. Errors from `device.poll` dropped with `let _ =`, so the FFI returns OK on GPU failure.
  **How to apply:** for every external-handle wrap, ask for runtime checks (device identity, size, format, usage) read from the handle itself, and that GPU wait/submit errors map to an error code.
- Multi-platform tasks split across branches (P1-001 iOS vs Android): flag that `task.py done` must wait for all parts, or the remaining part gets its own task/note.
  P1-002 (2026-10-19): the task title is almost entirely the Android path (AHardwareBuffer, Vulkan YCbCr, Plan B) but the branch did iOS only. Read the title: if the deferred half IS the risk being tested, closing on the easy half is wrong; require keep-in_progress or a user-approved split.
- Swift passing ObjC objects to C as `Unmanaged.passUnretained(x).toOpaque()` (P1-002 spike): Swift may release a local after its last use, i.e. before the C call runs. Ask for `withExtendedLifetime`.
- Pub `&self` GPU APIs that `queue.write_buffer` into one shared uniform per call (P1-002 draw_nv12): Gpu is Sync and shared via a static OnceLock, so two threads race (writes apply at the next submit). Ask for per-variant prebuilt buffers/bind groups instead.
- Zero-copy wrap of pooled decoder buffers: "retained, caller may release" docs ignore that the decoder pool recycles the IOSurface while the wgpu texture still lives. Ask that the contract cover the frame's whole use, not just "finished writing".
- Task marked done before review (REL-024, 2026-10-15): implementer ran `task.py done` and committed it before the reviewer ran, against CLAUDE.md "Mark done only after reviewer approved". Check `git log` for a "mark <ID> done" commit in the reviewed range; flag Warning.
- App icon assets (REL-024): Android adaptive safe zone is a 66dp-diameter CIRCLE centred at (54,54), not the 21..87 square; circle masks clip at radius 36. Compute the farthest content corner's distance from centre (sharp corners especially). minSdk 29 means legacy mipmap ic_launcher.png are never used (anydpi-v26 always wins).
- Untrusted-file decoders (P1-009 project codec): a byte cap (64 MiB) is not a count cap. Replaying decoded items through Timeline::insert_clip (Vec::insert) is O(n^2) on reverse-ordered clips (hang), and 2-byte empty repeated messages amplify ~16x in prost + Timeline (OOM). Also proto3 decode of a 0-byte file succeeds with all defaults, so format_version/min_reader_version 0 = "valid empty project" (truncated file opens empty, autosave then rotates good backups out).
  **How to apply:** for every proto/file decoder ask for: version field != 0 required, item-count caps, sorted-order check so inserts append; compute the worst-case file by hand.
- Negative-path tests ("refuses X", "failed op keeps state") pass against stubs that return Err (P1-009: 3 of 13). They still guard once implemented, so Suggestion only; flag if they are the ONLY test for a rule.
- Foundation absorption seen again P1-009: atomic save + backups (OVL-029, SYS-003), min reader version (OVL-031), untrusted project validation (SEC-001) implemented while those stay todo.
- Read-side caps without write-side caps (P1-009 re-review): decode refuses >MAX_TRACKS/MAX_CLIPS/4 MiB, but AddTrack/InsertClip/save enforce nothing, so the engine can save a file it then refuses to open, and backups rotate into the same state. Byte cap lived in storage while its rationale (prost memory) is the decoder's.
  **How to apply:** whenever a loader gains a limit, check the editor/saver enforces the same limit (refuse the edit or the save), and that the limit has one home.
- Rust+Dart tagged tasks shipped engine-only because the UI has nothing to act on yet (P1-018 clip ops: Dart shows only a clip count, no clips until P1-011 import). Do not let `task.py done` close the Dart tag silently: require a `task.py add` follow-up for the UI (naming its blockers) plus a note on the original task.
- No-op edits still push an undo step and clear redo (P1-010 fixed it for aspect ratio only; P1-018 TrimClip to the same edges repeats it). For every new edit command ask "can this be a no-op?" and check it is filtered before History::apply.
- Unrelated commits from another task ride along on a task branch (P1-018 branch carried the P1-005 plan doc + note). Flag Warning: one task per branch.
- Full-state "set" commands built from Dart's mirrored state (P1-026 SetTrackFlags sends all 3 flags from the last event): two taps before the event returns = lost update (second command reverts the first). Ask for per-field `optional` presence or a toggle/patch command so the engine merges.
- Order-dependent restore with an untested order (P1-026: decode applies lock AFTER inserting clips, but the round-trip test used a locked track with no clips). For any "apply X after Y on load" comment, require a fixture that would fail if the order flipped.
- State stored with no consumer yet (P1-026 mute/hide with no render/mix path): require a task.py note/add so the future preview/export/mix task honors it.
- Timeline clip ops each re-implement the neighbour-overlap check (insert_clip, trim_clip, move_clip at P1-019 = third copy of the same rule). For every new clip op, grep `partition_point` / `Overlap(` in core/timeline.rs and flag a Warning to extract one helper (start, end, skip-id) -> insert index.
  Resolved at P1-019: private `free_slot(clips, start, end, skip)` serves insert/move; trim deliberately keeps a neighbour-only check (free_slot would let a trim jump past a neighbour without re-sorting). New clip ops must reuse free_slot, not a fourth copy.
- Proptest-regressions seeds appended in impl/refactor commits touch frozen test paths but only add cases; accept (Suggestion at most), not a frozen-test violation.
- New timeline ops land with example tests only, no proptest (P1-019 move_clip), and symmetric branches go half-tested (self-skip on the prev side never exercised: replacing `.rev().find(..)` with `.last()` passes). Mutate each branch mentally; ask for an Ok-iff-model proptest (sorted + non-overlapping + move-back restores).
- Engine-only close variant: P1-019 was tagged Dart ONLY (title = drag UI), so closing it after engine work means zero Dart work under a Dart task. Require a task.py add for the UI naming blockers (P1-011, P1-045, UX-008 long-press drag) + note.
- ColorScheme role remaps have hidden consumers (DS-010, 2026-10-15): material_ui 1.5.0 M3 chips (Choice/Filter/Action/Input, unselected flat side) and M3E outlined icon buttons draw their boundary with `outlineVariant`, not `outline`; `outlineVariant` unset falls back to onBackground (high contrast). Mapping outlineVariant to a low-contrast divider token silently drops chip boundaries to ~1.4:1 while every test stays green.
  **How to apply:** for any theme/ColorScheme change, grep `_colors.<role>` in ~/.pub-cache/hosted/pub.dev/material_ui-*/lib/src for each changed role and check every widget the app uses against it; ask for a widget test on the real control (pump it, read its side color), not just scheme == token.
- Ids kept from untrusted files (P1-011: SavedMedia ids and v1 clip media_ids fed to reserve_ids_through). `next_id = max(id)` with id = u64::MAX makes the unchecked `allocate_id` (`+= 1`) panic in debug and wrap to 0 in release, so a later import's `media.insert(new_id)` overwrites existing media.
  **How to apply:** whenever a loader keeps or reserves ids from a file, require an upper bound (refuse ids above a cap) or a checked allocator, plus a u64::MAX test.
- Grow-only registries (P1-011 Timeline media map: deleting a clip never removes its media) slip past save-side caps keyed on clip count. Check that encode_for_save covers every collection decode caps.
- Frozen-test assertion deleted in the impl commit with "ids are reassigned" as the reason (P1-011 `assert_eq!(opened, tl)`). The test was wrong, but deleting it left media kind/duration and clip spans unchecked (saving a video as Image still passes). Ask for a structural replacement (compare Media values and clip spans), not deletion.
- Native picker/probe adapters (P1-011 Swift+Kotlin over `framix/media`): check every native-produced field against the engine's validator, per platform. Seen: Android sent MediaExtractor MIME ("video/x-vnd.on2.vp9" = 19 B, "video/dolby-vision" = 18 B) while iOS sent fourCC, and the engine caps codec at 16 B with all-or-nothing import, so a whole batch fails silently. Same field, two vocabularies.
  Also: Android sentinels (BitmapFactory outWidth = -1) hit Dart protobuf uint32 setters, which throw ArgumentError (not PlatformException), so `on PlatformException` adapters leak an unhandled error.
  **How to apply:** list each native value's worst case (missing key, unsupported format) and walk it through Dart proto setters and the engine's limits; ask for a mock-MethodChannel test of the Dart adapter.
- Copy-into-container importers (iOS Application Support/media) leave orphan files when the engine refuses the batch, the import is undone, or the clip is deleted; registry-prune tasks forget the files on disk. Ask for a file GC task/note.
- Target-cfg code outside the gate (P1-001 Android, 2026-10-18): check.sh runs clippy/tests for the macOS host only, so `#[cfg(target_os = "android")]` code (JNI entries, wgpu Android surface) is never linted; cross-compile CI is REL-010. Ask the implementer to run `cargo clippy --target aarch64-linux-android -- -D warnings` and report it.
- Manual native-ref release after code that can panic (P1-001 ANativeWindow): wgpu's default error handler PANICS on validation errors (surface.configure), ffi_guard catches it, but the `ANativeWindow_release` after the call never runs -> leaked ref. Ask for a Drop guard owning the ref.
- Toolchain pins vs the 14-day age rule (TC-011, 2026-10-19): pins often land to match a constraint already on main (pubspec sdk ^3.13.5 needed Flutter 3.47.7, 11 days old) while pubspec's own comment claims "every version is at least 14 days old". Ask for a task.py note recording the exception and the date it becomes compliant. Partial pins also belong to human-owned umbrella TC-002; ask for a note there.
- Raw native GPU submits behind wgpu (P1-056 android.rs, 2026-10-19): `vkQueueSubmit` on `hal.raw_queue()` bypasses wgpu-core's queue serialization; VkQueue needs external sync (also vkQueuePresentKHR). The private fn's "no other thread submits" contract was NOT carried into the pub `unsafe fn` # Safety docs, and Kotlin calls the JNI entries from the main thread (create) AND a worker Thread. Ask for a lock covering wgpu submit/present + raw submit, and the requirement in every pub unsafe doc up the chain.
  Same review: wgpu-hal on Vulkan 1.0 enables no external_memory/dedicated_allocation/ycbcr extensions, so adding VK_ANDROID_external_memory_android_hardware_buffer alone is invalid there; gate on api_version >= 1.1. Check AHB usage bits and size vs max dimension from AHardwareBuffer_describe.
  Kotlin `Thread { ... }.start()` with throwing MediaCodec/EGL/IO calls crashes the app (default uncaught handler); `codec.stop()` in finally throws if configure failed. Ask for runCatching + guarded cleanup.
- Task title names one approach, branch ships another the user chose (P1-056 title: VkSamplerYcbcrConversion; shipped GLES pass). Require a task.py note recording the decision before done. Also watch uncommitted stale notes citing squashed WIP commits ("WIP commit 4578485 ... emulator not done").
- Doc-only ADRs citing framework behaviour (P1-003 ADR 0004, 2026-10-20): claims read like source facts but combine incompatible options. Flutter 3.47.7: under SurfaceLifecycle.manual the ImageReader producer is never added as a trim listener, so onSurfaceCleanup/onSurfaceAvailable never fire (SurfaceTextureSurfaceProducer.setCallback is a no-op); getSurface() returns a NEW Surface after setSize; ImageReader path skips the acquire fence on API < 33 ("can't wait on the fence").
  **How to apply:** for every "do X on callback Y" in an ADR, trace in the framework source that Y fires under the configuration the ADR picks; flag notes filed from the ADR into other tasks too.
- JNI shims (P1-052 android_platform.rs, 2026-10-20), three things debug-emulator testing never shows:
  (1) Kotlin methods called ONLY from Rust via GetMethodID (createPreviewTexture, frameAvailable) get stripped by R8: Flutter's Gradle plugin sets release isMinifyEnabled = true (FlutterPlugin.kt:218) and the default rules keep only `native` methods. Require @Keep or proguard-rules.pro, and a `flutter run --release` check.
  (2) AttachCurrentThreadAsDaemon with no detach: ART aborts when an attached native thread exits ("Native thread exited without calling DetachCurrentThread"), so engine_destroy joining the engine thread = process abort. Ask for detach-on-exit (TLS Drop guard) or attach/detach per call.
  (3) Process-wide OnceLock registration of an Activity-scoped object (FlutterEngine renderer): Activity recreate (back on API 29/30 finishes the root activity) leaves the global ref on the dead engine's TextureRegistry. Ask for a process-scoped Kotlin object whose registry is swapped in configure/cleanUpFlutterEngine.
  **How to apply:** for any new JNI upcall or register-once API, check R8 keep, thread detach, and lifetime of the registered object vs the process.
- No-code closures citing another task's work (P1-013 -> P1-011, 2026-10-21): the cited --commit was the engine-only commit, while the claimed platform readers landed 2 commits later (and the owning task recorded its final fix commit). `git show --stat <sha>` must contain every file the closure note names; prefer the owning task's final commit.
  Also check that new follow-up tasks do not re-own pieces of existing tasks (P1-059 "minimal FFmpeg build" = SYS-024), and that a "fallback for what the platform cannot read" is reachable: both pickers DROP unprobeable files (iOS deletes the copy), so the fallback never sees them.
  EXIF/transform mapping to rotation-only silently drops mirroring (orientations 2/4/5/7, negative-det preferredTransform); RawMedia has no mirror flag.
- Secondary step after a committed edit turns success into CommandFailed (P1-020, 2026-10-21): handle() applied the edit (history pushed), then a playhead-clamp redraw failed and the reply became CommandFailed, breaking "CommandFailed = timeline unchanged"; Dart's mirror goes stale. Reachable whenever the GPU is unusable, because Preview.shown was set before the first draw failed. Same for Seek: state moved, reply says failed.
  **How to apply:** for every handle()/reply path, list what mutates before each `?`; a fallible side effect (draw, notify, save) after a commit must not change the reply. Ask for a failing-fake test.
- Flutter scrub rebuild scope (P1-020): a playhead Positioned in the same Stack as a CustomPaint ruler and clip boxes re-lays out the Stack, so every playhead event repaints the ruler (shouldRepaint only gates painter swaps). Check for RepaintBoundary around static timeline content and that painters cull to the visible range (ruler drew TextPainters over the full scroll width).
- Microtask-per-turn coalescing of pointer-driven commands is a no-op on devices (one pointer event per turn, 120-240 Hz touch); real latest-wins belongs on the engine side (command queue drain) or per frame.
- Height from `textScaler.scale(<summed px>)` (P1-020 re-review): Flutter 3.47's system TextScaler calls platformDispatcher.scaleFontSize, which is NONLINEAR on Android 14+ (large sizes scale less), so scaling a 52px sum under-sizes two 14px lines at 200%. Tests with textScaleFactorTestValue are linear and miss it. Ask to scale each font size, or let the text box size itself.
- "Best effort" fixes that drop the error with `Err(_) =>` and disable the feature permanently (preview `shown = None`): check that the failure is surfaced (event/log) so the UI can recover, and that the disable path has a test.
- Unkeyed per-slot widgets in a scrolled/zoomed list (P1-021 ThumbnailTile, 2026-10-21): a side effect (engine request) fired only in initState/didChangeDependencies never fires when Flutter REUSES the State for a new slot (scroll shifts `first`, zoom-out, clip reorder); only didUpdateWidget runs. Tests that only count tiles after zoom-in pass. Ask for didUpdateWidget (or a ValueKey per item) plus a scroll test that expects the new request.
- Caches keyed by engine ids (media/clip ids) that restart at 1 on NewProject/OpenProject (History::default / decode => fresh Timeline next_id): engine dedup sets and Dart maps keyed by id then skip or show the OLD project's data. For any id-keyed cache, check it is reset on project switch, with a test.
  Seen again P1-060 (2026-10-24): "redraw only if LayerKey changed" (key = MediaId + source time + transform + canvas) skips the redraw after OpenProject/EnableAutosave with the playhead already at 0, because two projects built the same way have equal keys -> old project's picture stays. Change-detection keys count as id-keyed caches too; project-swap paths (NewProject, OpenProject, EnableAutosave load) must force the redraw.
- Untrusted i64 from Seek/commands in new math (P1-022 Timeline::snap, 2026-10-21): `(p.0 - time.0).abs()` overflows for time = i64::MIN (debug panic; release wraps to a negative "distance" so it snaps wrongly). Proptests sampled -100..600 only. Ask for abs_diff/saturating math and an extreme-value test whenever a core fn takes engine-command ints.
- Decode-time per-item edits that go through a locate-by-id API (P1-029 decode calls set_clip_transform(id) per clip; `locate` is a linear scan over all clips): decode becomes O(n^2) up to MAX_CLIPS=100k (~5e9 compares) on a crafted file, though insert was kept linear on purpose. When a loader applies a post-insert setter, check its cost per call, or validate/set via the inserted index.
- check.sh flake: first `fvm flutter test` run can fail on native_assets install_name_tool "cannot rename ... XXXXXX (No such file)" (stale app/build); a rerun is green. Rerun before calling it Critical.
- Flutter ScaleGestureRecognizer state (TC-012 re-review, 2026-10-23): onScaleEnd fires only from _reconfigure while state==started. After lift-one-of-two the state is `accepted`, so lifting the LAST finger without a move in between emits NO onScaleEnd (pointerCount 0 never arrives). Any "clear on onScaleEnd(pointerCount==0)" logic leaves stale state; clear via a Listener pointer count (down/up/cancel) instead. Also: on a new pointer-down in `accepted` state the recognizer fires onStart + onUpdate with the focal-jump delta.
